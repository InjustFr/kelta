# branch-script

Act on a ticket or a work item from a plugin (walkthrough: `docs/plugins-guide/acting-on-work.md`).

- `kelta-plugin.toml` adds "Run script on this branch" to the work menu (`work_actions`) and to the ticket
  detail (`ticket_actions`). Both open the `run` screen with `params = { work = "{work.id}", ticket = "{ticket.key}" }`.
- `dist/app.js` reads the work item (`work.get`, or `work.list` matched on `ticket.key`), shows its branch,
  worktree, ticket and PR, and runs `./run.sh <script> <branch> <worktree>` in the worktree with `exec.run`.
  The last 10 runs are kept with `kv.*`; `work.updated` and `pr.merged` refresh the screen.
- `run.sh` runs the `script` setting (default `echo`, so out of the box it prints the branch and worktree).
  Set it in Settings → Plugins → Branch script, e.g. `make deploy-qa`.
- `dist/kelta-sdk.js` is a vendored copy of `@kelta/plugin-sdk` (regenerated by the SDK tests:
  `KELTA_UPDATE_VENDOR=1 pnpm --filter @kelta/plugin-sdk test`).
- Permissions: `work.read`, `exec:run.sh`, `storage`, `events:work.updated`, `events:pr.merged`, `ui.open`
  (the actions open the screen). Remove one and the matching call fails with `permission_denied`.
