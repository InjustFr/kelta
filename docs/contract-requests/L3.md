# L3 — contract requests and deviations

## Deviations (implemented locally, inside L3 paths)

1. **`work_items.session_ids_json` column** (ARCHITECTURE §10). `WorkItem.session_ids` must
   round-trip through `WorkStore`, and §10 has no column for it. The v1 migration adds
   `session_ids_json TEXT NOT NULL DEFAULT '[]'`. Request: add the column to §10.
2. **`sid8` collisions with uuid v7** (ARCHITECTURE §2.1, `SessionId::generate`). The first 8 hex
   chars of a uuid v7 are the top 32 bits of the ms timestamp, so every session spawned in the same
   ~65 s window shares a `<sid8>`. The required collision check would then spin until the clock
   moves on. Workaround in `Core::new_session_id`: on collision, retry with a uuid v4 (random
   prefix). Request: either make `SessionId::generate` use v4, or define `<sid8>` from the random
   tail of the v7 uuid.
3. **Additive `kelta-core` API** (no frozen signature changed): `CoreDeps` + `Core::start_with`
   (dependency injection for tests and the desktop shell; `Core::start` keeps its signature and
   builds the real services), `ConfigBackend` (settings + project CRUD), `Core::scheduler_snapshot`,
   and the public modules listed in `lib.rs`.

4. **`reqwest` added to `kelta-core/Cargo.toml`** (`reqwest = { workspace = true }`, the
   workspace pin, no new crate in the build; `Cargo.lock` gains one line). Plugin `http_fetch`
   must not follow redirects (a 3xx to another host bypasses the `net:<host>` grant, ARCHITECTURE
   §11.3), reqwest has no per-request redirect policy, and the shared `HttpClient` follows them.
   `ctl::http_fetch` now uses its own `Policy::none()` client and returns 3xx as-is.
   Request: either accept the dependency, or have `kelta-http` (L5) expose a no-redirect client
   (`HttpClient::no_redirect()`), and L3 switches to it.
5. **sid8 reservation**: `Core::new_session_id` reserves each handed-out `<sid8>` in
   `Core::sid8_taken` under one lock, so concurrent spawns / templates never share a runtime dir.
   Reserved sid8s are never freed during a run (8 bytes per spawn).

## Requests

The ones in items 2 and 4 above.
