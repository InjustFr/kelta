# L10 contract requests and deviations

1. **Linux app id** (`tauri.conf.json`, scaffold-owned): `dev.kelta.Kelta` as GTK app id / Wayland app_id needs `"app": { "enableGTKAppId": true }`. L10 sets it in `packaging/tauri.release.json` only, so release builds are correct and dev builds (`cargo run`) keep the binary name. Please add it to `tauri.conf.json`.
2. **`app_ready`** (`commands/app.rs`, not L10): it should call `kelta_desktop::platform::launch_succeeded()` (drops the launch crash guard) and `window::bench::mark("app_ready_ms", t_ms)`. Workaround in `window::create`: `on_page_load(Finished)` does both, so the guard is cleared and the bench gets an approximate value even before `app_ready` is wired.
3. **`.gitignore`**: add `apps/desktop/src-tauri/binaries/` (the `kelta-ctl-<triple>` sidecar built by `packaging/build.sh`).
4. **Custom decorations** (`window.decorations = "custom"`): Rust side only removes the system title bar. The UI shell must render the drag region (`data-tauri-drag-region`) and resize handles (`getCurrentWindow().startResizeDragging(dir)`), and capability `main` must grant `core:window:allow-start-dragging` and `core:window:allow-start-resize-dragging`. The effective mode is not exposed to the UI yet; suggested: an `app_info` field or `?decorations=` query. L10 does not append it.
5. **Bench metrics from the app**: `kelta-bench` scenarios switch, echo-latency, ink-redraw, flood (and cold-start) read a JSON object from the file named by `KELTA_BENCH_MARKS`. Keys: `app_ready_ms`; `switch_warm_ms`, `switch_cold_ms`; `echo_frames_p95`, `keydown_to_pty_p99_ms`; `frame_p95_ms`; `frame_max_ms`, `webview_delta_mb`, `inflight_kib`. `window::bench::mark(key, value)` merges a key into that file (no-op without the env var). The terminal/UI lanes (L1, L2, L3) call it from their instrumentation. Until then those scenarios time out ("did not report"); `--dry-run` uses canned values.
6. **Background scenario** relies on the ctl `emit` command `custom.bench.close_window` being forwarded by core to `UiBridge::emit` as `UiEvent::CtlCommand`. It is honoured only when `KELTA_BENCH_MARKS` is set.
7. **XDG activation token**: `CtlCommand::Toggle` carries no token, so a hotkey-launched `kelta-ctl toggle` cannot hand its `XDG_ACTIVATION_TOKEN` to the running instance (GTK consumes the variable at process start). `window::raise` uses `set_focus` only (see `shortcut:` comment). Request: `Toggle { activation_token: Option<String> }` read by `kelta-ctl` from the environment.
8. **Focus events on the bus**: no bus publisher is reachable from the desktop crate, so `on_window_event` does not publish `window.focus`. Request: a `Core` method for it.
9. **Baseline**: `bench/fixtures/baseline.json` (kept inside the owned `bench/fixtures/**`) starts empty; `--update-baseline` on a real run writes it. Dry runs never write it.
10. **CI validation**: `desktop-file-validate` and `appstreamcli validate` run in `release.yml` and `nightly.yml` (Linux job). `ci.yml` is not L10-owned; add the same step there if wanted.
11. **Not verified locally**: universal dmg (Homebrew cargo has no cross targets), deb and AppImage (Linux/Docker, run by the orchestrator at integration), and the workflows on GitHub. `desktop-file-validate`/`appstreamcli` are absent on the dev machine.
