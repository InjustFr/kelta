# L6 — Work orchestration: contract requests and deviations

All items below are implemented with a local workaround inside `crates/kelta-work`; the requests are
for the merge owner (scaffold-owned files / other lanes).

## Requests

1. **Wiring `WorkHost` (core, L3).** `WorkService` needs two services it cannot reach through
   `CoreApi`: the lazy HTTP server port (`kelta_server::Server::ensure_http` / `release_http`, for
   `mcp.json` and `claude.hook_transport = "http"`) and the blocking trigger runner
   (`kelta_plugins::PluginHost::run_blocking`, for `ticket.before_start`, `pr.before_create`,
   `work.before_finish`). Added `pub trait kelta_work::WorkHost { ensure_http, release_http,
   run_blocking }` and `WorkService::set_host(Arc<dyn WorkHost>)`. Core should implement it over its
   `Server` and `PluginHost` and call `work.set_host(..)` right after `WorkService::new`.
   Without a host: Claude starts without `--mcp-config` (HTTP hooks fall back to command hooks) and
   blocking pre-events are only published on the bus (no veto/patch). Consumer accounting: kelta-work
   takes one `ensure_http` per Claude session it spawns and releases it on that session's
   `session.exited` (or on finish); core should not count Claude sessions spawned by kelta-work twice.
   Alternative: add `CoreApi::http_port()` and `CoreApi::run_blocking(&BusEvent)`.

2. **Kelta session id before spawn (proto `SpawnRequest`, core L3).** `mcp.json`
   (`/mcp/<sid>`) and HTTP hooks (`/hook/<sid>`) must name the Kelta session id before Claude starts,
   but `SpawnRequest` has no id. Workaround: kelta-work pre-generates a `SessionId` and passes it as
   `env["KELTA_SESSION_ID"]`; if core returns another id, the files are rewritten immediately after
   `session_spawn` returns (before Claude reads them, but it is a race in principle). Request: add
   `SpawnRequest.id: Option<SessionId>` (core uses it when present), or have core honour a valid uuid
   in `env["KELTA_SESSION_ID"]`.

3. **`work.updated` to the UI (core L3).** `CoreApi` has no UI emit. kelta-work publishes a bus event
   named `work.updated` with payload `{ "work": WorkItem }` (const `kelta_work::WORK_UPDATED`) on every
   item/step change; core should relay it as `UiEvent::WorkUpdated { work }` (and may hide it from
   triggers). Alternative: `CoreApi::emit(UiEvent)`.

4. **`<sid8>` collisions (proto `SessionId::sid8`).** Session ids are uuid v7, whose first 8 hex
   digits are the high bits of the millisecond timestamp: every session created within ~65 s shares
   the same `sid8`. kelta-work therefore names its per-session runtime dirs `<runtime>/s/<key8>/` with
   `key8` = first 8 hex digits of the (v4) Claude `--session-id` uuid, or random for editors,
   allocated with exclusive `mkdir` (collision-checked, 0700). Core should not assume
   `<runtime>/s/<sid8>/` == the session's dir for work-item sessions (the nvim socket path is in
   `WorkItem.nvim_socket`). Suggest proto derive `sid8` from the random part of the uuid.

5. **Dormant Claude restore (core L3).** Core restores Dormant sessions from `RestorePolicy`; for
   Claude it needs the full argv (`--settings`, `--mcp-config`, … whose files live in the runtime dir
   that a reboot wipes). Added `WorkService::claude_restore_request(session, fallback) ->
   Option<SpawnRequest>`: core should call it when attaching a Dormant `ClaudeResume` session that
   belongs to a work item (`fallback = true` after a refused `--resume`, i.e. a fast non-zero exit).
   `work_resume` already does this itself (`--resume`, then `--continue` if it exits non-zero within
   5 s).

6. **`EditorMeta.socket` (core L3).** kelta-work spawns nvim with `--listen <runtime>/s/<key8>/nvim.sock`
   and records it in `WorkItem.nvim_socket`; `editor_open` / `send_selection` / follow-edits /
   `quit_hook` fall back to it when `SessionInfo.editor.socket` is `None`. Core may fill
   `EditorMeta.socket` from the `--listen` argument for consistency.

7. **`work_retry_step` Skip (L9 UI).** There is no `work_skip_step` command. `work_retry_step` accepts
   `step = "skip:<step>"` to mark a failed step skipped and continue the saga ("Continue anyway" after
   a failed setup). A plain step id re-runs that step (`setup` respawns the setup session,
   `tracker_side_effects` re-applies the effects).

8. **Project listing for `startup` (CoreApi).** `git worktree prune` runs at startup for the repos of
   known work items only (`CoreApi` cannot list projects). Request `CoreApi::projects()` if every
   project repo should be pruned.

## Deviations / clarifications

- **Template layout:** `layout_open` can only split the focused pane and has no ratios. The template
  tree is materialised top-down (first leaf of each split child, then recursion), focusing anchors
  with `Placement::Focused` + `Terminal{session_id}`; ratios are left to core (equal split). The
  `layout` step opens the tab with a `PaneContent::WorkItem` progress pane, which the first template
  leaf replaces (`ReplaceFocused`) once the sessions exist; a setup pane is split below it.
- **Setup commands** run in one visible `Setup` session as `/bin/sh -c 'set -e; …'` where every
  command is shell-words split and each word POSIX-quoted (the shell only sequences argv vectors; no
  user text is shell-parsed).
- **`--allowedTools`** is passed as one comma-joined value so the variadic option cannot swallow the
  positional prompt; a prompt starting with `-` is preceded by `--`.
- **`claude --version` gate** resolves `claude.binary` with the process `PATH` (no `LoginEnv` in
  `CoreApi`); when not found the gate is skipped (core reports `NotFound` at spawn).
- **`repo_rules.match.component`:** tickets carry no component field; components are matched against
  ticket labels (`label`, `type` match labels / issue type).
- **Plan prompt:** rendered at plan time leniently, so `{run}` (unknown until start) stays literal in
  the editable prompt and is resolved when Claude is launched.
- **Finish transition:** `FinishOpts.transition_to = None` uses `status_map.done`, then
  `work.on_merge.transition_to` when a PR exists. Untracked copies of `worktree.include` files do not
  make a worktree dirty (they are removed with it).
- **Dirty error detail:** `{ "files": [..], "unpushed": bool, "unpushed_commits": n }`.
- **Saga journal:** the plan and the side effects already performed are journaled in
  `<data>/work/<work_item_id>.json` (0600) next to the `work_steps` rows, so a crash after any step
  resumes without duplicating worktrees, sessions, tabs or tracker calls. `startup()` turns sagas left
  in `starting` into `Failed { step, "interrupted …" }` so the UI offers Retry/Skip.
