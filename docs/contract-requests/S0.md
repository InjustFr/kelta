## Contract deviations / clarifications (merge owner please confirm)

1. **`ProviderFactory` lives in `kelta_http::provider`**, re-exported as `kelta_http::ProviderFactory`, not in `kelta_proto::api`. Its signature takes `kelta_http::HttpCtx`, and kelta-http depends on kelta-proto, so the trait cannot sit in proto without a dependency cycle. Signature unchanged.
2. **`kelta_plugins::uri::handle(host: &PluginHost, req)`** takes the host as its first argument (the handler needs the plugin directories). The desktop registers `kelta-plugin://` via `register_asynchronous_uri_scheme_protocol` and calls it with `core.plugins()`.
3. **`keys.bindings` default is `{}`** (overrides only), not "platform defaults". Defaults differ per OS, and a platform-dependent default would make `schema/settings.schema.json` differ between macOS and Linux (codegen drift). Platform defaults live in the ActionId catalog (`kelta_proto::actions::ACTIONS` → `ui/src/lib/gen/actions.ts`, with both `mac` and `linux` chords); effective bindings = catalog defaults ⊕ `keys.bindings`. `keys.prefix_bindings` is platform-independent and does default to the SPEC §4 prefix keys.
4. **clippy `disallowed-methods`** follows BUILD_PLAN §2.6 (`tokio::time::interval`, `interval_at`, `std::thread::sleep`, `std::thread::spawn`, `std::process::exit`). `tokio::time::sleep` (ARCHITECTURE §13) is **not** disallowed, because BUILD_PLAN rule 5 allows event-armed one-shots (`// one-shot: <reason>`). The list applies workspace-wide; allowlisted modules use `#[allow(clippy::disallowed_methods)] // allowlisted: …`. Binaries return `ExitCode` instead of calling `process::exit`. `tauri::generate_context!` expands to `process::exit`, so it sits in an allowlisted `fn context()` in the desktop `lib.rs`.
5. **`StatusChange.status` for "unchanged"**: hook events that leave the status unchanged (`PostToolUse` with `file_edited`) use `SessionStatus::Unknown`; core keeps the previous status (documented on the type; `FakeCore` behaves this way).
6. **`CtlCommand::Hook.payload` is `Box<HookPayload>`** in Rust (clippy `large_enum_variant`); the wire format is unchanged.
7. **Enum wire format**: every enum serializes in `snake_case` (`ErrorCode` → `"not_found"`, `SessionStatus` → `"needs_input"`, `StatusCategory` → `"in_progress"`), except `PermissionMode` (camelCase, Claude's own values `acceptEdits`, `dontAsk`, …), `ClaudeEffort` (lowercase), `Osc52`/`ShiftEnter` (kebab: `read-write`, `esc-cr`), `PluginMethod` (`"tickets.list"`) and `Permission` (its string form). Tagged unions: `UiEvent` tag `type`, `SessionKind` tag `type`, `LayoutNode` tag `type`, `PaneContent` tag `kind`, `Scope`/`RestorePolicy`/`WorkState`/`WorkSource`/`ToolHandle`/`EditorTarget`/`Assignee` tag `kind`, `Cursor` adjacently tagged `{kind, value}`, `ActionDef` tag `action`, `CtlCommand` tag `cmd`.
8. **`Option` fields serialize as `null`** (TS `T | null`); missing keys deserialize to `None`. `u64`/`i64` map to TS `number` (ts-rs `large_int = number`).
9. **Extra DTOs** not spelled out in ARCHITECTURE but needed by signatures: `PaneRef`, `ProjectPatch`, `RepoDraft`, `CodeHostHint`, `TrackerHint`, `SubscribeResult {sub_id}`, `LayoutSaveResult {rev}`, `ScreenOpenResult {instance_id, url}`, `ToolSource`, `TriggerOrigin`, `CallOrigin`, `PermissionInfo`, `PluginGrant`, `BlockingOutcome`, `ProxiedRequest/Response`, `SessionTermStats`, `LoginEnv`, `TerminalLimits`, `TerminalPalette`, `SettingsDiff`, `RuntimeOverrides`, `CliArgs`, `ReviewQuery`, `Reviewer`, `CiCheck`, `FileChange`, `PrCreate`, `ClaudePlan`, `SideEffects`, `BranchExists`, plus SQLite row structs in `kelta_proto::store` (§10). `StartWorkPlan` has an extra `repo_choices: Vec<String>` (the repo picker).
10. **Stub API additions** beyond BUILD_PLAN §2.2 (needed by commands): `ConfigService::{effective_doc, set_plugin_schemas, dirs, overrides}`, `WorkService::for_session`, `PluginHost::{trigger_test, trigger_log}`, `Core` accessors (`dirs, cli, bridge, config, secrets, secret_resolver, terminal, http, tracker_factory, code_host_factory, work, server, plugins, app_info, shutdown`), `UiBridge::webview_pids` (default method, for `perf_snapshot`), `window::on_second_instance` (single-instance callback).
11. **`session_write` wire format**: the command takes the raw `tauri::ipc::Request`. Accepted: raw `Uint8Array` body + header `x-kelta-session-id`, or JSON `{id, data}` with `data` as a number array, an index-keyed object (a JSON-serialized `Uint8Array`) or a string (`commands::parse_session_write`). The UI wrapper should prefer the raw form.
12. **`tauri.conf.json` has `"windows": []`**: the main window is created by `window::setup` (L10), so decorations/geometry can be decided at runtime. Capability `main` grants `core:default` + `allow-<command>` for all 89 commands to the window labelled `main`, local origin only.
13. **`devUrl` is `http://localhost:5173`** (Vite default) and `frontendDist` is `../../../ui/dist`. If the UI dev server uses another port, `tauri.conf.json` must follow.
14. **Commands that work in the stub**: `app_info` and `events_subscribe` (pass-through to the bridge, whose stub drops events). All other commands return `Unsupported("not implemented: <command>")`.
15. **Fixtures are generated** from typed samples (`kelta_proto::samples`) by `xtask codegen` into `crates/kelta-proto/fixtures/*.json` (98 files), so `codegen --check` also covers them. `ui/src/lib/gen/fixtures.ts` embeds them typed (svelte-check/tsc catches serde ↔ ts-rs drift); `ui/src/lib/gen/fixtures.test.ts` (vitest) round-trips them. The generated TS uses double quotes and ts-rs formatting: prettier/eslint should ignore `ui/src/lib/gen/**`.
16. **JSON schemas** inline subschemas (no `$ref`) except recursive types (`TemplateNode`, `Matcher`, `ActionDef`), which keep `$defs`.

## Deviations / clarifications

1. **`manualChunks` → `codeSplitting`**: Vite 8 builds with rolldown, where `output.manualChunks` is deprecated. `ui/vite.config.ts` uses `build.rolldownOptions.output.codeSplitting.groups` with one `xterm` group (xterm core + the eager fit/unicode11/web-links addons). The WebGL and search addons stay dynamic imports. Views are lazy through `src/app/registry.ts`.
2. **Registry contracts** (`ui/src/app/registry.ts`): besides the four registries it exports the frozen prop types `PaneProps<K>`, `TabHeaderProps`, `SheetProps` (`onclose` + spread props) and `SettingsSectionProps`. Pane kind `empty` has no registry entry (the shell renders it). Settings section files are PascalCase (`views/settings/sections/LinuxGraphics.svelte`, `views/plugins/sections/Tools.svelte`, …).
3. **Action modules**: `main.ts` eager-loads `ui/src/shell/actions.ts` and `ui/src/views/*/actions.ts` via `import.meta.glob`. Empty stubs exist for L2 (`shell/actions.ts`), L9 (`views/{tickets,reviews,work}/actions.ts`), L4 (`views/settings/actions.ts`) and L8 (`views/{tools,plugins}/actions.ts`). `plugin.command.<id>` falls back to a handler registered as `plugin.command.*` (args get `command_id`).
4. **L2 stubs created by the scaffold**: `ui/src/lib/terminal/index.ts` (`TerminalViewPool`) and `ui/src/lib/keys/index.ts` (`parseChord`, `matchChord`, `findConflicts`, `KeyManager`). They are inert (`findConflicts` returns `[]`, `parseChord` returns `null`, `TerminalViewPool.show` rejects), so L4 can import them before L2 merges.
5. **IPC wrappers** (`ui/src/lib/ipc/commands.ts`): the `Commands` map gives args/result types for all 89 commands; camelCase wrappers take the snake_case argument object (`projectClose({ id, kill_sessions })`). `sessionAttach(args, onFrame)` and `eventsSubscribe(onEvent)` create the channel; `sessionWrite(id, bytes|string)` sends the raw body with the `x-kelta-session-id` header. Every rejection is an `IpcError` (`code`, `detail`, `retryAfterMs`, `command`). A vitest test checks `COMMAND_NAMES` against `apps/desktop/src-tauri/src/commands/names.rs`.
6. **`app_ready`** is called by `main.ts` in the first `requestAnimationFrame` after mounting the shell (single call, not recursive).
7. **Mock debug handles**: with `VITE_IPC=mock`, `main.ts` exposes `window.__keltaMock` (fail next/always, emit UiEvents, terminal output, call log, reset) and `window.__kelta` (`stores`, `registry`, `actions`) for Playwright. They do not exist in Tauri builds.
8. **Mock data**: 3 projects + Home, 10 sessions, tickets for jira-acme / redmine-corp / github-oss / gitlab-corp (GitLab tickets and one review are unbound → "Other"), 6 reviews, 3 work items (active, failed step, PR open). `work_finish` on the failed item without `force` returns `Dirty`; Jira "Done" transitions return `NeedsFields`; `review_approve` checks `head_sha`.
9. **Ports**: `vite` dev server is `127.0.0.1:5173` (`strictPort`, matches `devUrl`); Playwright runs its own dev server on `5179` with `VITE_IPC=mock`.
10. **Lint**: ESLint also forbids `setInterval` (`no-restricted-globals` / `no-restricted-properties`), on top of `scripts/check-no-timers.sh`. `ui/src/lib/gen/**` is ignored by ESLint and Prettier.
11. **plugin-sdk**: `package.json` `exports` points at `src/index.ts` (no build needed inside the workspace; `build` emits `dist/` for publishing). The stub `connect()` rejects with `not implemented: connect`.
12. **Desktop build against `ui/dist`**: a plain dev `cargo build -p kelta-desktop` uses `devUrl` and does not embed assets. Embedding the real `ui/dist` was verified with `cargo build -p kelta-desktop --locked --features tauri/custom-protocol` (the hashed asset names are in the binary).
