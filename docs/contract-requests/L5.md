# L5 — Providers: HTTP, trackers, code hosts — deviations and requests

No shared contract (kelta-proto, manifests, generated code) was edited. Every public signature of the
scaffold (`HttpClient::new`, `HttpCtx::new`, `send_json`, `send_text`, `markdown::{to_html, sanitize}`,
`ProviderFactory`, `TrackerFactory`, `CodeHostFactory`) is unchanged; everything below is additive or a
behaviour the merge owner / core (L3) should know about.

## Requests for core / the merge owner

1. **`reviews.ticket_key_regex` reaches the code hosts through a process-wide setter.**
   `ProviderFactory::code_host` carries no settings and `CodeHostFactory` is a unit struct, so the regex
   cannot be injected per provider. `kelta_codehosts::set_ticket_key_regex(pattern) -> Result<(), KeltaError>`
   swaps it (invalid patterns are rejected, the previous one stays). Core should call it at startup and on
   settings reload; the default is the SETTINGS.md default (`[A-Z][A-Z0-9]+-\d+|#\d+`). `linked_tickets(&[branch, title])`
   is also exported.
2. **Rate-limit contract for the scheduler (ARCH §8.3/§8.4).** `HttpCtx` sleeps inline only for waits
   <= 5 s (Retry-After, rate-limit reset, jittered backoff, max 3 retries). Longer waits fail fast with
   `RateLimited { retry_after_ms }` and the account stays blocked inside its `HttpCtx` (later calls fail
   fast with the remaining time, no request leaves). The scheduler should pause the account for
   `retry_after_ms`. `HttpCtx::blocked_for()` exposes the remaining time. `401 -> NeedsAuth` additionally
   calls `SecretResolver::invalidate` (through `kelta_http::Authed`). Offline -> `Network` (no retry).
3. **Providers must be recreated, not reused, when account settings change** (flavor, `me`, Projects v2 field
   metadata and the GitLab scope list are cached for the provider's lifetime; there are no timers).
4. **Wire details the UI/work lanes rely on:**
   - Transition ids are discovered, never constants: Jira numeric transition ids; Redmine status ids;
     GitHub Issues `open` / `closed` (no project) or `status:<option name>` (Projects v2, option and field ids
     resolved by name and cached); GitLab `label:<scope>::<value>` / `close` / `reopen`. A GitLab Done-category
     scoped label also closes the issue (and then replaces the plain `close` transition).
   - `TicketRef.key`: Jira `SHOP-123`, Redmine `4567`, GitHub `owner/repo#12`, GitLab `group/sub/project#12`
     (so API calls need no extra lookup); `branch_key`: `SHOP-123`, `4567`, `gh-12`, `gl-12`.
   - Jira Cloud `Cursor::Token` is opaque (`"<pages fetched>:<nextPageToken>"`) so the 20-page cap survives
     across calls; the first request carries no `nextPageToken` key.
   - `NeedsFields` detail (Jira): `{"fields": [{"id", "name", "message", "required", "type", "allowed_values"}], "error_messages": [...]}`.
   - Redmine 422 stays `InvalidArgument` with the Redmine messages in `message` and `detail.errors`.
5. **SETTINGS.md §3 tracker view keys reused by GitHub Issues**: `status` (`open|closed|*`) and
   `assigned_to` (`me|any`, per-repo views) are documented under redmine but also honoured for github; gitlab
   uses `status` too. Docs could list them as shared keys.

## Behaviour notes (no action needed, recorded for reviewers)

- `HttpResponse.status` is `304` (with `not_modified = true` and the cached body) when the ETag cache answers.
- `status_error` now stores the first 4 KiB of the response body in `detail.body` (providers parse Jira
  `errors`, Redmine 422, GitHub 422). Request `Debug` redacts `Authorization`, `PRIVATE-TOKEN`, `X-Redmine-API-Key`
  and query values.
- New additive API in kelta-http: `HttpClient::with_timeout(ua, Option<Duration>)` (`None` = no timeout and no
  pooling, i.e. no timers: required by paused-time tests, otherwise the runtime auto-advances to reqwest's own
  timers), `HttpRequest::patch`, `HttpCtx::blocked_for`, modules `auth` (`Authed`, `AuthScheme`), `graphql`, `util`
  (percent-encoding, `Link` paging, host helpers), `markdown::plain_to_html` (Textile / Jira wiki shown preformatted).
- GitHub code host: `list_reviews` sends one GraphQL request with both aliases (`reviewRequested`, `authored`) as
  ARCH §8.2 describes and returns the alias of `q.kind` (the other half is discarded). `changed_since_last` returns
  `Ok(false)` without a request while inside the last `X-Poll-Interval`, `Ok(true)` for fine-grained / app tokens
  (`github_pat_`, `ghs_`, `ghu_`) and after a 403/404 on `/notifications` (gate disabled for the provider's life).
  The gate only sees participating notifications (review requests), not CI changes of authored PRs.
- GitLab code host: MRs untouched for 90 days are not listed (`updated_after`, day granularity so the ETag URL is
  stable); `draft=no` / `wip=no` depends on `GET /version` (>= 16 uses `draft`; a failing `/version` assumes recent);
  request-changes = note + best-effort unapprove; the todos gate compares (count, max id) of pending
  `review_requested` todos.
- Redmine `Ticket.project_hint` is the project id (issue payloads carry no identifier). Jira `auto` flavor detection
  calls `GET /rest/api/2/serverInfo` anonymously and falls back to the host name (`*.atlassian.net` = Cloud) when it
  answers with an error.
- Fixtures under `crates/kelta-trackers/fixtures` and `crates/kelta-codehosts/fixtures` are hand-written in the
  shape of the real payloads (no recording was possible offline).
