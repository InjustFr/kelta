# Kelta v0.1 — Build plan (scaffold + 10 parallel lanes)

Executed by parallel AI agents, each in its own git clone, with **disjoint file ownership**. Agents cannot talk to each other: everything they share is frozen by the scaffold. Read ARCHITECTURE.md (contract), SPEC.md (product), SETTINGS.md, PLUGINS.md before starting.

## 1. Rules for every lane

1. Edit **only** paths you own (§3). Never edit scaffold-owned files (manifests, `kelta-proto`, generated code, `ui/src/lib/{ipc,gen,stores,ui,layout}`, registries, CI skeleton, scripts). If a contract is missing or wrong, implement the best local workaround inside your paths and write the request to `docs/contract-requests/<lane-id>.md` (each lane owns its own file). The merge owner resolves requests after merge.
2. Dependencies: use only those already declared in the crate's `Cargo.toml` / `ui/package.json` (scaffold pins every dependency of every lane). Need another one → contract request.
3. Stubs: scaffold stubs return `Err(KeltaError{code: Unsupported, message: "not implemented: <fn>"})` (Rust) or render `<NotImplemented name="…"/>` (Svelte). Replace every stub in your paths; keep public signatures exactly.
4. Tests must run headless (no display, no network) on macOS and in the Ubuntu container. Provider tests use recorded fixtures + `wiremock`. Tests needing optional binaries (`nvim`, `git`, `sl`) skip with a message when absent (`git` and `nvim` exist in the CI image).
5. Performance rules are part of the contract: no `setInterval`, no recursive rAF, no `tokio::time::interval`, no ad hoc `thread::spawn`/`sleep` (lint-enforced; allowlisted modules only: `kelta-core::scheduler`, `kelta-core::store`, `kelta-term::reader`, tests, `ui/src/lib/terminal/raf.ts`). One-shot timers are allowed only when armed by an event and named in a comment `// one-shot: <reason>`.
6. Done = all QA commands (§7) pass in your clone on macOS and in Docker, your acceptance criteria are met, and `docs/contract-requests/<lane-id>.md` lists any deviations (or "none").

## 2. Scaffold step (S0) — runs first, alone (opus/high)

Goal: a repository where **every crate, command, view, store and test target exists, compiles, lints and passes** with stubs, so each lane can work and test in isolation.

### 2.6 Lint config details
- `clippy.toml` `disallowed-methods` (workspace-wide): `tokio::time::interval`, `tokio::time::interval_at`, `std::thread::sleep`, `std::thread::spawn` (allow via `#[allow(clippy::disallowed_methods)]` with a `// allowlisted:` comment only in the allowlisted modules), `std::process::exit` (binaries return `ExitCode`; the desktop wraps `tauri::generate_context!`, which expands to `process::exit`, in an allowlisted `fn context()`). `tokio::time::sleep` is not lint-banned (event-armed one-shots, rule 1.5). `clippy.toml` allows `unwrap`/`expect` in tests.
- `scripts/check-no-timers.sh`: greps `ui/src` and `packages/plugin-sdk/src` for `setInterval(` and for `requestAnimationFrame` inside a function that calls itself (heuristic: `requestAnimationFrame(fn)` where `fn` is defined earlier in the same file); allowlist `ui/src/lib/terminal/raf.ts`, `ui/src/lib/gen`, tests. It also scans `crates/` and `apps/` Rust for unallowlisted `thread::spawn`/`thread::sleep` (outside tests and the allowlisted modules; a `// allowlisted:` comment within the two previous lines accepts a line). ESLint additionally forbids `setInterval`; `ui/src/lib/gen/**` is ignored by ESLint and Prettier.

## 4. Lanes

### L1 — Terminal backend (`kelta-term`) · opus / high
Why: PTY lifecycle, threads, flow control and a byte-exact snapshot encoder are the hardest correctness code; a missed DEC mode silently breaks nvim/Claude after every project switch.
- **Replaces stubs:** `PtyTerminalHost::new` and every `TerminalHost` method; `resolve_login_env`.
- **Implements:** ARCH §7.1-7.4, §9.3, §9.5: `PtyBackend` trait with portable-pty impl + rustix openpty/fork fallback (feature `rustix-pty`); direct exec with complete env; setsid/process group kill; reader thread (256 KiB stack) with `poll` + DEC 2026 `sync_timeout`/`stop_sync`; EAGAIN input queue; alacritty `Term` with `kitty_keyboard=false`; `EventListener` → `TerminalEvents` (title, bell, clipboard, PtyWrite replies, ColorRequest from palette); OSC 7/9/777 pre-scan; attach/detach with generation; frames 0x01/0x02/0x03; HIGH/LOW watermarks; snapshot catch-up; ack watchdog (5 s one-shot only while inflight > 0); resize ordering; scrollback per kind + global memory cap shrink; `text_tail`; `stats`; exit/waitpid. Record the exact answered query set in `docs/contracts/terminal-queries.md` and a contract request if it differs from `SWALLOWED_QUERIES`.
- **Consumes:** `kelta-proto` types only.
- **Tests:** unit (frame codec, watermark state machine with fake sink, palette replies, OSC pre-scan, login-env sentinel parser with noisy rc output); PTY integration with `/bin/sh` and `tui-sim` (spawn/exit codes, kill process group, resize → SIGWINCH observed, `--flood 50` keeps inflight ≤ 256 KiB and ends with a snapshot, `--ink` sync timeout flush, `--queries` answered exactly once); **snapshot round-trip goldens**: for every recording in `fixtures/recordings/` (record with nvim --clean, tui-sim modes, a Claude-like ink stream, lazygit-like alt screen + mouse) feed Term A, encode snapshot, feed into fresh Term B, assert identical grid cells, attributes, cursor, modes, title (+ insta snapshot of the bytes); criterion benches (parse throughput ≥ 200 MB/s, snapshot 200×60+1000 lines ≤ 15 ms).
- **Acceptance:** all above green on macOS and Docker; 10 idle sessions with 500 lines each add ≤ 20 MB RSS in a test binary; no thread or fd leak after 100 spawn/kill cycles.

## 5. Merge, contract changes, integration

- Merge owner (the orchestrator) merges lanes in this order: **L1 → L3 → L2 → L10** (enables gates G1/G2) → **L4, L5, L7** → **L6** → **L8** → **L9**. Conflicts are impossible by construction except in `Cargo.lock`/`pnpm-lock.yaml` (regenerate; versions are pinned) and generated files (re-run `xtask codegen`).
- After each merge: full QA (§7) on macOS + Docker. Failures are fixed by the owning lane's agent (re-run with the failure log) — never by editing another lane's files.
- Contract requests are batched after all merges; accepted changes are applied by the merge owner to scaffold-owned files and the affected lanes re-run.
